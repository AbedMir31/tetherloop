## Audit context (one paragraph)

TetherLoop is a Swift 6 / SwiftPM macOS 14+ menu bar app (~1,900 source lines, 35 passing tests, clean adapter architecture). The audit's headline finding, reproduced live on the maintainer's machine (macOS 26.4.1): `networksetup -getairportnetwork` reports "not associated" while connected, because Apple privacy-gated SSID reads behind Location Services — so the app's automatic failover never fires on modern macOS (plan 005). Secondary trust bugs: pause/protection-toggle don't stop failover (001), pause is lost on settings changes (002), sleep assertion desyncs from the toggle (003), `networksetup` join failures masquerade as success (006), notifications crash unbundled runs (004). PRD coverage: 21 of 26 V1 stories genuinely done; story 8 (pre-test warning) missing, 9/17 partial (007).

## Findings considered and rejected

- **FileDiagnosticLogStore rewrites the whole file per append** — bounded at 500 events; cost is negligible; not worth changing.
- **`AppModel.record` reloads all events on every append** — same scale argument.
- **Test fakes (`FakeNetworkAdapter`, `Recording*`, `InMemory*`) live in the production target** — used by `AppModel.preview()` and `GenerateScreenshots`; moving them would break those; acceptable for this repo's size.
- **`DiagnosticEvent.redact` only handles `password=`-style patterns** — log inputs are app-generated; SSIDs are intentionally allowed per PRD; no stronger redaction needed in V1.
- **`defaultTrustedSSIDIfNeeded` auto-trusts the current network when the trusted list is empty** — debatable UX but deliberate, logged, and low-risk (protection still requires verification + explicit enable). Characterized by tests in plan 008; product call left to the maintainer.
- **`ProcessSnapshotProvider` unused in V1** — documented PRD groundwork for Pro process detection; keep.
- **5-second polling spawns a `networksetup` process per tick** — works and is simple; event-driven CoreWLAN monitoring is recorded as a direction follow-up in plan 005's maintenance notes, not a V1 fix.
- **Pause not persisted across app restart** — runtime-only by design today; noted in plan 002's maintenance notes as a possible follow-up, not a bug fix.
